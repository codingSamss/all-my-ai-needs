# Changelog

## 1.0.0-rc.23

- 修复信箱在没有任何脚本或子代理时一直亮着：用 rc.22 的 `/buddy-status` 在出问题的会话里读出，宿主快照列着一个 running 的任务 `shbjycjln`，不是脚本也不是代理。它的 ID 前缀 `s` 对应宿主的 `monitor_ws` 任务（CLI 自己的任务类型表），该会话又确实发布过 Artifact，评论监视处于已武装状态：这是宿主为已发布的 Artifact 挂的监视，整个会话期间一直 running，会出现在 Stop 的 `background_tasks` 里，所以每次主会话空闲都被当成在等回信。Stop 载荷里 `type` 字段本身没有直接抓到，判断依据是 ID 规则加会话里的监视记录；重载后在该会话里看信箱是否消失即可核实。
- 现在把宿主的订阅类与内部维护类任务排除在等待之外：监视（`monitor`、`monitor_ws`、`monitor_mcp`）、记忆整理（`dream`）、自动模式扫描、记忆导入。按快照里的 `type` 标签判断，标签对不上时再按宿主生成任务 ID 的规则兜底（监视 `s` / `m`、整理 `d`、扫描 `e`、导入 `n` 加 8 位字母数字）；脚本（`b`）、代理（`a`）、工作流（`w`）等不受影响，没有 `type` 字段的旧式快照条目照常计入。
- 同会话热重载接续后台记录时，也不再带过旧版记进来的这类任务，所以升级重载后信箱立即消失，不必等下一次主回合结束的快照。
- `/buddy-status` 增加两项：每个后台任务显示宿主快照里的类型；被忽略的监视类任务单独列在「宿主列出但不计入等待」下。类型文字限长、异常字符会被替换，快照里最多记 30 条。
- 未增加网络、文件读取、模型调用或轮询。CLI 内核 2.1.299 的 102 项 SDK 测试（新增 5 项，改写 6 处旧断言的输出格式）与 13 项安装器测试通过；把六处写法分别改回去，对应用例各自失败。
- 状态：作者于 2026-10-18 放行 rc.23，没有做原生 App 新会话实测；`mods.meta.yaml` 状态由 candidate 改为 owner-accepted，仍为 manual-only。

## 1.0.0-rc.22

- 只新增一个只读诊断入口，画面、SVG、状态优先级、后台追踪规则、底栏和安装器与 rc.21 相同。起因是「没有任何后台任务却仍显示等回信」：外部读不到插件此刻记着什么，没法判断是宿主真有在途任务，还是插件记错，所以先让它可以被读出来，不凭猜测再改判断规则。
- 新命令 `/buddy-status`：列出画面阶段、有没有拿到过宿主快照、信箱依据（在途调用数加后台任务数）、每个后台任务的 ID 及它是否被宿主快照确认（宿主快照确认在跑 / 快照之后登记 / 尚无快照）和在代理列表里的状态，以及代理列表 `agent.list()` 的 ID、状态和类型、已收到终态的任务数；每段最多列 20 行。重载后尚未经主回合结束时的快照校正的条目，会标成「尚无快照，未经确认」。
- 只打印 ID、状态和类型，不含代理描述、名称、命令内容或路径，异常字符会被替换。命令登记为 immediate，回合进行中也能运行；输出和其他命令一样写入对话记录，模型读得到。
- 命令只读：不写面板状态、不重载、不增加轮询，运行时读一次面板状态和一次代理列表。登记失败或代理列表读取失败只影响这个诊断入口，不影响动画。
- CLI 内核 2.1.299 的 97 项 SDK 测试（新增 8 项）与 13 项安装器测试通过，官方静态验证把该命令归为「回答自己命令」。把命令的五处写法分别改坏，对应用例各自失败；另在真机无头会话里起一个后台子代理后运行该命令，列出该子代理为「宿主快照确认在跑」，代理列表中为 running。原生 App 新会话验收待做，保持 candidate。

## 1.0.0-rc.21

- 只加固后台等待（等回信）的归并，画面、SVG、状态优先级、底栏和安装器与 rc.20 相同。针对 rc.19 空闲一个多小时后邮箱仍亮着的现象，复查出四处会让等待残留的缺口并修复；原始现象本身没能在真机复现，是否已根治仍需新会话观察。
- 子代理自己启动的后台脚本：宿主向子代理投递完成通知时，会在信封前加一段固定的「系统通知，非用户输入」声明（有时再包一层 `system-reminder`）。旧版只认以信封开头的文本，认不出，这类任务要等下一份完整快照才会清掉。现在信封紧跟这段声明时同样识别；声明之外的前缀仍一律不认，来源也仍须是宿主 task-notification。
- 通知终态补上 `stopped`：宿主续接会话时，会为上一个进程没留下完成记录的任务补发这一条，此后不会再有完成通知；旧版忽略它。
- Stop / SubagentStop 快照里出现不认识的状态词时，只忽略那一条（按未列出处理），整份快照仍有效，过期的等待照常清掉；旧版会因一个新状态词作废整份快照。缺 ID、缺状态、非对象或 ID 不合法的条目仍使整份快照不可信，沿用保留已确认任务的规则。
- 主回合结束（含中断、出错）时清掉仍没返回的前台工具调用；此前它只靠每次调用自己的收尾清除，被宿主放弃的调用会让等待一直亮着。此后新登记的调用不受影响，后台任务另在任务表里跟踪。
- 未增加网络、文件读取、模型调用或轮询。CLI 内核 2.1.299 的 89 项 SDK 与 13 项安装器测试通过，后台追踪新增 17 项；把三处修复分别还原成 rc.20 的写法，对应用例各自失败。宿主声明原文取自真机采样。原生 App 新会话验收待做，保持 candidate。

## 1.0.0-rc.20

- 宠物改住同一间固定小房间：书架、挂帘的窗户、绿植、落地灯、软木板、挂画、带植物的矮柜和地毯。原先每种状态一个地点的七景背景取消，状态只更换中间 80×27 逻辑像素舞台里的动作和道具；陈设全部静止，睡觉时窗外变夜、落地灯熄灭，大面积底色仍透明。

- 状态由七种增至十二种：新增思考、回复、等你、出错、中断；等回信、压缩、未知、完成和睡觉沿用，休息的咖啡按 cache 剩余寿命分热、温、凉三档。
- 思考、干活、回复来自 `turn.step` 响应块的种类（thinking / text / tool），不读取文本内容；子代理的请求不改变主画面。
- 等你只覆盖 `AskUserQuestion` 与 `ExitPlanMode`，计数方式与压缩相同，作答、拒绝、抛错和并发都能收回；普通工具权限确认与执行同在一次 `tool.call` 内，插件无法区分，不显示等你。
- 主回合以 error、refusal 结束显示出错，被中断显示中断，各约 6 秒后交还给未知或后台等待；子代理自己的失败不触发。
- 咖啡温度借用现有 1 秒节拍判断，只在跨过半寿命和过期时写一次面板，秒级倒计时仍不重绘宠物。
